เวอร์ชัน Demo สำหรับใช้งานบน GitHub Pages

============================================================
1. ภาพรวมของระบบ
============================================================

KU Facility Service Center เป็นเว็บสำหรับแจ้งซ่อมและติดตามงานซ่อมบำรุง
เช่น งานอาคาร งานท่อน้ำ งานไฟฟ้า งานแสงสว่าง และงานบำรุงรักษาทั่วไป

ระบบนี้เป็นเว็บแบบ static web app สามารถเปิดใช้งานผ่าน browser ได้ทันที
และสามารถอัปขึ้น GitHub Pages เพื่อให้เปิดใช้งานผ่าน URL ได้

ข้อมูลในระบบจะถูกเก็บไว้ใน browser ด้วย localStorage
หมายความว่า:

- ข้อมูลอยู่ในเครื่อง/browser ที่ใช้งาน
- ถ้าเปลี่ยนเครื่องหรือเปลี่ยน browser จะไม่เห็นข้อมูลงานเดิม
- เหมาะสำหรับ demo, ทดลองใช้งาน, หรือใช้งานแบบเครื่องเดียว
- หากต้องการใช้งานจริงหลายคนพร้อมกัน ควรเพิ่ม backend/database ส่วนกลาง

============================================================
3. หน้าแรกและ Dashboard
============================================================

หน้าแรกจะแสดงภาพรวมงานทั้งหมดในระบบ ได้แก่

1. แจ้งงาน
   แสดงจำนวนงานที่มีผู้แจ้งเข้ามาแล้ว แต่เจ้าหน้าที่ยังไม่ได้เริ่มดำเนินงาน

2. กำลังดำเนินงาน
   แสดงจำนวนงานที่เจ้าหน้าที่กดรับเรื่องหรือเริ่มดำเนินงานแล้ว

3. งานเสร็จแล้ว
   แสดงจำนวนงานที่เจ้าหน้าที่ปิดงานเรียบร้อยแล้ว

4. งานเร่งด่วน
   แสดงจำนวนงานที่ถูกแจ้งเป็นระดับเร่งด่วนหรือวิกฤต

5. งานทั้งหมด
   แสดงจำนวนงานทั้งหมดในระบบ

6. ความคืบหน้างานทั้งหมด
   แสดงเป็นเปอร์เซ็นต์ โดยคำนวณจาก
   งานเสร็จแล้ว / งานทั้งหมด x 100

ตัวอย่าง:
ถ้ามีงานทั้งหมด 2 งาน และเสร็จแล้ว 1 งาน
ความคืบหน้าจะแสดงเป็น 50%

============================================================
5. สถานะของงาน
============================================================

ระบบมีสถานะงานหลักดังนี้

1. แจ้งงาน
   หมายถึง มีผู้แจ้งงานเข้ามาแล้ว แต่เจ้าหน้าที่ยังไม่ได้กดรับเรื่อง

2. กำลังดำเนินงาน
   หมายถึง เจ้าหน้าที่กดเริ่มดำเนินงานแล้ว
   ระบบจะบันทึกเวลาเริ่มดำเนินงานไว้

3. งานเสร็จแล้ว
   หมายถึง เจ้าหน้าที่ปิดงานแล้ว พร้อมบันทึกรายละเอียดหลังทำ
   และอัปโหลดรูปหลังทำ

4. ยกเลิกงาน
   หมายถึง งานถูกยกเลิกโดยเจ้าหน้าที่
   งานจะไม่ถูกลบออกทันที เพื่อให้ยังมีประวัติใน Activity Log

============================================================
6. การรับเรื่องหรือเริ่มดำเนินงาน
============================================================

เมื่อมีผู้แจ้งงานเข้ามา งานจะแสดงในรายการงานเป็นสถานะ "แจ้งงาน"

ขั้นตอนให้เจ้าหน้าที่รับเรื่อง:

1. ไปที่รายการงาน
2. กดปุ่ม "ดูรายละเอียด" ของงานที่ต้องการ
3. ในหน้ารายละเอียด กดปุ่ม "เริ่มดำเนินงาน"
4. ระบบจะให้กรอกรหัสเจ้าหน้าที่
5. ใส่รหัส 123
6. ระบบจะเปลี่ยนสถานะเป็น "กำลังดำเนินงาน"

หลังจากกดเริ่มดำเนินงาน ระบบจะบันทึกเวลาไว้เพื่อใช้คำนวณระยะเวลา
เช่น:

- เวลารอตั้งแต่แจ้งงานจนเจ้าหน้าที่เริ่มดำเนินงาน
- เวลาดำเนินงานตั้งแต่รับเรื่องจนปิดงาน
- อายุงานรวมตั้งแต่แจ้งงานจนถึงสถานะปัจจุบัน

============================================================
7. การปิดงาน
============================================================

เมื่อดำเนินงานเสร็จแล้ว ให้เจ้าหน้าที่ปิดงานดังนี้

1. ไปที่แท็บ "ปิดงาน"
2. กรอกรหัสเจ้าหน้าที่เป็น 123
3. กรอกรหัสงาน เช่น MAPM-260816-001
4. กรอกรายละเอียดหลังดำเนินการ
5. อัปโหลดรูปหลังทำ
6. กดปุ่มอัปเดตงานเสร็จแล้ว

เมื่อปิดงานแล้ว ระบบจะ:

- เปลี่ยนสถานะเป็น "งานเสร็จแล้ว"
- บันทึกเวลาปิดงาน
- บันทึกรูปหลังทำ
- บันทึกรายละเอียดการแก้ไข
- อัปเดตเปอร์เซ็นต์ความคืบหน้าบน Dashboard

============================================================
8. การส่งอีเมลแจ้งสถานะผ่าน Gmail
============================================================

ระบบมีช่องอีเมลผู้แจ้งในฟอร์มแจ้งงาน
และมีปุ่ม "ส่งอีเมลผ่าน Gmail" ในหน้ารายละเอียดงาน

วิธีใช้งาน:

1. เปิดรายละเอียดงาน
2. ตรวจสอบว่ามีอีเมลผู้แจ้ง
3. กดปุ่ม "ส่งอีเมลผ่าน Gmail"
4. ระบบจะเปิดหน้า Gmail compose
5. Gmail จะกรอกข้อมูลให้อัตโนมัติ ได้แก่
   - อีเมลผู้รับ
   - หัวข้ออีเมล
   - รหัสงาน
   - สถานะงาน
   - อาคารและชั้น
   - อาการที่แจ้ง
   - รายละเอียดการดำเนินงาน ถ้ามี
6. เจ้าหน้าที่ตรวจสอบข้อความ
7. กดส่งอีเมลใน Gmail

ข้อจำกัด:
ระบบนี้ยังไม่ได้ส่งอีเมลอัตโนมัติจาก server
เพราะ GitHub Pages เป็น static hosting และไม่สามารถเก็บ Gmail token
หรือรหัสผ่านอย่างปลอดภัยในหน้าเว็บได้

หากต้องการส่งอีเมลอัตโนมัติจริง ควรเพิ่ม backend เช่น:

- Google Apps Script
- Firebase Functions
- Supabase Edge Functions
- Gmail API ผ่าน server
- Email service เช่น SendGrid, Resend, Mailgun

============================================================
10. กราฟเปรียบเทียบ
============================================================

ระบบมีกราฟแท่งสำหรับดูภาพรวมและเปรียบเทียบงาน

ตัวกรองที่มี:

1. เปรียบเทียบตามสถานะงาน
   แสดงจำนวนงานในแต่ละสถานะ เช่น แจ้งงาน กำลังดำเนินงาน เสร็จแล้ว เร่งด่วน และทั้งหมด

2. เปรียบเทียบตามอาคาร
   แสดงจำนวนงานแยกตามอาคาร

3. เปรียบเทียบตามเดือน
   แสดงจำนวนงานแยกตามเดือน

สีของกราฟและสถานะ:

- แจ้งงาน ใช้สีเหลือง
- กำลังดำเนินงาน ใช้สีฟ้า
- งานเสร็จแล้ว ใช้สีเขียว
- งานเร่งด่วน ใช้สีแดง
- งานทั้งหมด ใช้สีเขียวเข้ม
- งานยกเลิก ใช้สีเทา

กราฟจะแสดงทั้งแท่งและค่าตัวเลข เพื่อให้ดูจำนวนงานได้ชัดเจน

11. การ Download รายงาน
============================================================

ระบบมีปุ่ม Download Excel และ Download JSON

Download Excel:

- ใช้ส่งออกรายงานประจำเดือน
- ไฟล์เป็น .xls
- เปิดด้วย Microsoft Excel ได้
- มีข้อมูลสรุปจำนวนงาน
- มีรายการงานในเดือนนั้น
- มีอีเมลผู้แจ้งรวมอยู่ในรายงาน

Download JSON:

- ใช้สำรองข้อมูลทั้งหมด
- เหมาะสำหรับ export/import กลับเข้าระบบ
- ใช้เก็บข้อมูลไว้ก่อนล้าง browser หรือย้ายเครื่อง

12. การ Import ข้อมูล
============================================================

ปุ่ม Import ใช้สำหรับนำไฟล์ JSON กลับเข้าระบบ

ขั้นตอน:

1. กดปุ่ม Import
2. เลือกไฟล์ JSON ที่เคย Download ไว้
3. ระบบจะตรวจสอบไฟล์
4. ถ้าข้อมูลถูกต้อง ระบบจะนำงานกลับมาแสดง

คำแนะนำ:
ควร Download JSON สำรองเป็นระยะ โดยเฉพาะก่อนเปลี่ยนเครื่อง
หรือล้างข้อมูล browser

14. Database Storage for Demo
============================================================

ระบบแสดงสถานะพื้นที่จัดเก็บข้อมูลในหัวข้อ
"Database Storage for Demo"

ข้อมูลที่แสดง:

- ขนาดข้อมูลที่ใช้ไป
- ขนาดสูงสุด 100 MB
- จำนวนงาน
- จำนวน log

ถ้าข้อมูลเกิน 100 MB ระบบจะพยายามล้างข้อมูลงานเก่าที่เสร็จแล้ว
หรืองานที่ถูกยกเลิกก่อน เพื่อไม่ให้ browser เก็บข้อมูลมากเกินไป

หมายเหตุ:
นี่เป็นการจำลอง database สำหรับ demo เท่านั้น
ไม่ใช่ database ส่วนกลางจริง

17. ข้อจำกัดของระบบ Demo
============================================================

ระบบนี้เป็น Demo ที่ทำงานบน GitHub Pages และ localStorage
จึงมีข้อจำกัดดังนี้:

1. ข้อมูลไม่ได้ sync ระหว่างเครื่อง
2. หลายคนเปิดคนละเครื่องจะไม่เห็นข้อมูลเดียวกัน
3. ไม่มีระบบ login จริง
4. ยังไม่มี backend/database ส่วนกลาง
5. ยังไม่ส่งอีเมลอัตโนมัติแบบ server-side
6. รูปภาพถูกเก็บใน browser ทำให้ข้อมูลมีขนาดใหญ่ได้
7. ถ้าล้าง browser data ข้อมูลอาจหาย

============================================================
18. คำแนะนำสำหรับใช้งานจริง
============================================================

หากต้องการพัฒนาต่อเพื่อใช้งานจริง ควรเพิ่มสิ่งต่อไปนี้:

1. Backend/database ส่วนกลาง
   เช่น Supabase, Firebase, PostgreSQL หรือ GitHub Issues API

2. ระบบ login และสิทธิ์ผู้ใช้
   แยกผู้แจ้งงาน เจ้าหน้าที่ ผู้ดูแลระบบ และผู้บริหาร

3. ระบบอีเมลอัตโนมัติ
   ส่งแจ้งเตือนเมื่อมีงานใหม่ รับงานแล้ว ปิดงานแล้ว หรือยกเลิกงาน

4. ระบบแนบไฟล์ที่ปลอดภัย
   เก็บรูปใน cloud storage แทน localStorage

5. รายงานขั้นสูง
   เช่น SLA, เวลาเฉลี่ยในการรับงาน, เวลาเฉลี่ยในการปิดงาน, งานแยกตามอาคาร

6. Dashboard สำหรับผู้บริหาร
   แสดง performance รายเดือน รายปี และงานค้างสะสม

7. ระบบสำรองข้อมูล
   Backup อัตโนมัติ และมีสิทธิ์เข้าถึงข้อมูลตามบทบาท
