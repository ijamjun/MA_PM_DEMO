คู่มือการใช้งานระบบ KU Facility Service Center
ระบบแจ้งซ่อมและบำรุงรักษา MA/PM

จัดทำสำหรับทดลองใช้งานระบบ Demo บน GitHub Pages

------------------------------------------------------------
1. ระบบนี้ใช้ทำอะไร
------------------------------------------------------------

KU Facility Service Center เป็นเว็บสำหรับรับแจ้งงานซ่อมและงานบำรุงรักษา
เช่น งานอาคาร ท่อน้ำ ไฟฟ้า แสงสว่าง หรือปัญหาอื่น ๆ ภายในพื้นที่ใช้งาน

ผู้แจ้งสามารถกรอกรายละเอียดปัญหา แนบรูป และรับรหัสงานไว้ติดตามได้
ส่วนเจ้าหน้าที่สามารถกดรับเรื่อง อัปเดตสถานะ ปิดงาน และออกรายงานได้

ระบบชุดนี้เป็นเวอร์ชัน Demo ข้อมูลจะเก็บไว้ใน browser ของเครื่องที่ใช้งาน
ไม่ได้เก็บลงฐานข้อมูลกลาง ดังนั้นถ้าเปิดจากคนละเครื่อง หรือคนละ browser
ข้อมูลอาจไม่ตรงกัน เหมาะสำหรับทดลองระบบ สาธิตการทำงาน หรือใช้เป็นต้นแบบ
ก่อนพัฒนาระบบจริง

เพราะการใช้รหัสเดียวกันทุกคนเหมาะกับการสาธิตเท่านั้น

------------------------------------------------------------
3. ส่วนประกอบบนหน้าแรก
------------------------------------------------------------

เมื่อเปิดเว็บขึ้นมา หน้าแรกจะแสดงภาพรวมของงานทั้งหมด ได้แก่

แจ้งงาน
คือจำนวนงานที่มีคนแจ้งเข้ามาแล้ว แต่เจ้าหน้าที่ยังไม่ได้กดเริ่มดำเนินงาน

กำลังดำเนินงาน
คืองานที่เจ้าหน้าที่กดรับเรื่องหรือเริ่มดำเนินงานแล้ว

งานเสร็จแล้ว
คืองานที่เจ้าหน้าที่ปิดงานเรียบร้อย พร้อมกรอกรายละเอียดหลังทำและแนบรูปหลังทำ

งานเร่งด่วน
คืองานที่เลือกความเร่งด่วนเป็นเร่งด่วนหรือวิกฤต

งานทั้งหมด
คือจำนวนงานทั้งหมดที่มีอยู่ในระบบ

ความคืบหน้างานทั้งหมด
แสดงเป็นเปอร์เซ็นต์ โดยคิดจากจำนวนงานที่เสร็จแล้วเทียบกับงานทั้งหมด
เช่น มีงานทั้งหมด 2 งาน เสร็จแล้ว 1 งาน ระบบจะแสดง 50%

4. วิธีแจ้งงานซ่อม
------------------------------------------------------------

ให้ผู้แจ้งทำตามขั้นตอนนี้

1. ไปที่แท็บ "แจ้งงาน"
2. ใส่รหัสผู้แจ้งงาน 123
3. กรอกชื่อผู้แจ้ง
4. กรอกอีเมลผู้แจ้ง
5. เลือกความเร่งด่วนของงาน
6. กรอกอาคาร
7. กรอกชั้น
8. กรอกรายละเอียดอาการเสียหาย
9. แนบรูปปัญหาก่อนดำเนินการ
10. กดปุ่มบันทึกงานแจ้งซ่อม

เมื่อบันทึกเสร็จ ระบบจะสร้างรหัสงานให้อัตโนมัติ เช่น
MAPM-260816-001

ให้จดหรือบันทึกรหัสนี้ไว้ เพราะใช้สำหรับค้นหา ดูรายละเอียด และปิดงาน

------------------------------------------------------------
5. ความหมายของสถานะงาน
------------------------------------------------------------

แจ้งงาน
มีการแจ้งปัญหาเข้ามาแล้ว แต่ยังไม่มีเจ้าหน้าที่กดเริ่มดำเนินงาน

กำลังดำเนินงาน
เจ้าหน้าที่รับเรื่องแล้ว และระบบเริ่มนับเวลาการดำเนินงาน

งานเสร็จแล้ว
เจ้าหน้าที่ปิดงานแล้ว มีรายละเอียดหลังทำและรูปหลังทำ

ยกเลิกงาน
เจ้าหน้าที่กดยกเลิกงาน งานจะยังอยู่ในระบบเพื่อดูประวัติย้อนหลัง
ไม่ได้ลบออกทันที

------------------------------------------------------------
6. วิธีที่เจ้าหน้าที่รับเรื่อง
------------------------------------------------------------

เมื่อมีงานใหม่เข้ามา งานจะอยู่ในสถานะ "แจ้งงาน"

วิธีรับเรื่องมีดังนี้

1. ไปที่รายการงาน
2. เลือกงานที่ต้องการ
3. กด "ดูรายละเอียด"
4. กดปุ่ม "เริ่มดำเนินงาน"
5. ใส่รหัสเจ้าหน้าที่ 123
6. ระบบจะเปลี่ยนสถานะเป็น "กำลังดำเนินงาน"

หลังจากกดเริ่มดำเนินงาน ระบบจะบันทึกเวลาไว้ให้ เช่น
เวลาที่รอก่อนรับเรื่อง และเวลาที่ใช้ดำเนินงาน

------------------------------------------------------------
7. วิธีปิดงาน
------------------------------------------------------------

เมื่อซ่อมหรือดำเนินการเสร็จแล้ว ให้ปิดงานตามนี้

1. ไปที่แท็บ "ปิดงาน"
2. ใส่รหัสเจ้าหน้าที่ 123
3. ใส่รหัสงาน เช่น MAPM-260816-001
4. กรอกรายละเอียดหลังดำเนินการ
5. แนบรูปหลังทำ
6. กดอัปเดตงานเสร็จแล้ว

เมื่อปิดงานแล้ว ระบบจะเปลี่ยนสถานะเป็นงานเสร็จแล้วทันที
Dashboard และเปอร์เซ็นต์ความคืบหน้าจะอัปเดตตามข้อมูลล่าสุด

------------------------------------------------------------
8. การส่งอีเมลผ่าน Gmail
------------------------------------------------------------

ในฟอร์มแจ้งงานมีช่องให้กรอกอีเมลผู้แจ้ง
อีเมลนี้จะถูกนำไปใช้ตอนเจ้าหน้าที่ต้องการแจ้งสถานะงาน

วิธีส่งอีเมล

1. เปิดรายละเอียดงาน
2. กดปุ่ม "ส่งอีเมลผ่าน Gmail"
3. ระบบจะเปิดหน้าเขียนอีเมลของ Gmail
4. ระบบจะกรอกอีเมลผู้รับ หัวข้อ และข้อความเบื้องต้นให้
5. เจ้าหน้าที่ตรวจสอบข้อความอีกครั้ง
6. กดส่งจากหน้า Gmail

หมายเหตุสำคัญ
ระบบนี้ยังไม่ได้ส่งอีเมลอัตโนมัติเอง เพราะเป็นเว็บบน GitHub Pages
ซึ่งไม่เหมาะกับการเก็บรหัสผ่านหรือ token ของ Gmail ไว้ในหน้าเว็บ
จึงใช้วิธีเปิด Gmail ให้เจ้าหน้าที่ตรวจสอบและกดส่งเอง ซึ่งปลอดภัยกว่า
สำหรับเวอร์ชัน Demo

ถ้าต้องการส่งอีเมลอัตโนมัติจริง ควรทำผ่าน backend หรือบริการส่งอีเมล
เช่น Google Apps Script, Firebase, Supabase, SendGrid หรือบริการลักษณะเดียวกัน

15. Database Storage for Demo
------------------------------------------------------------

------------------------------------------------------------
18. ข้อจำกัดของระบบ Demo
------------------------------------------------------------

ควรทราบข้อจำกัดเหล่านี้ก่อนใช้งาน

1. ข้อมูลเก็บใน browser ไม่ใช่ฐานข้อมูลกลาง
2. เปลี่ยนเครื่องหรือเปลี่ยน browser แล้วข้อมูลอาจไม่ตามไปด้วย
3. ยังไม่มีระบบ login จริง
4. ยังไม่รองรับการใช้งานหลายคนพร้อมกันแบบสมบูรณ์
5. การส่งอีเมลเป็นการเปิด Gmail ให้เจ้าหน้าที่กดส่งเอง
6. รูปภาพที่แนบจะทำให้ข้อมูลใน browser มีขนาดใหญ่ขึ้น
7. ถ้าล้างข้อมูล browser ข้อมูลในระบบอาจหาย

เพราะฉะนั้นถ้าใช้สาธิตหรือทดลองระบบสามารถใช้ได้เลย
แต่ถ้าจะใช้จริงในหน่วยงาน ควรพัฒนา backend และฐานข้อมูลกลางเพิ่มเติม

------------------------------------------------------------
19. สิ่งที่ควรเพิ่มหากพัฒนาต่อ
------------------------------------------------------------

ถ้าต้องการทำให้ระบบพร้อมใช้งานจริง แนะนำให้เพิ่มส่วนต่อไปนี้

1. ระบบ login
แยกสิทธิ์ผู้แจ้ง เจ้าหน้าที่ หัวหน้างาน และผู้ดูแลระบบ

2. ฐานข้อมูลกลาง
เช่น Supabase, Firebase, PostgreSQL หรือฐานข้อมูลของหน่วยงาน

3. ระบบส่งอีเมลอัตโนมัติ
แจ้งเตือนเมื่อมีงานใหม่ รับงานแล้ว ปิดงานแล้ว หรือยกเลิกงาน

4. ระบบเก็บรูปภาพบน cloud
เพื่อลดภาระ localStorage ใน browser

5. รายงานสำหรับผู้บริหาร
เช่น งานค้างสะสม เวลาเฉลี่ยในการรับงาน เวลาเฉลี่ยในการปิดงาน และสรุปรายเดือน

6. ระบบ SLA
กำหนดเวลาที่ควรรับเรื่องและควรปิดงานตามระดับความเร่งด่วน

7. ระบบ Backup
สำรองข้อมูลอัตโนมัติ เพื่อป้องกันข้อมูลสูญหาย
